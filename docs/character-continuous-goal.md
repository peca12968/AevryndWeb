# Aevrynd 新世代仿真人物持續目標

## 核心任務

持續建立並優化一套由 Aevrynd 完整持有、可離線製作、可直接整合進自研引擎的仿真人物系統。Blender 是製作與驗證工具，最終網格、骨架、動畫、材質、貼圖、毛髮資料、碰撞資料、LOD 與匯入程式必須成為 Aevrynd 引擎資產及程式的一部分，不得依賴 MetaHuman、Unreal Engine、訂閱服務或會造成後續授權費與平台綁定的執行元件。

先完成新女性角色。只有使用者明確確認女性角色品質可以接受後，才可用已驗證的方法開始男性角色。

## 新模型策略

1. 保留既有 `v249/r1128` 女性角色為可回退對照，不覆寫歷史版本。
2. 建立新的女性角色主線與獨立 Blender 原始檔，重新處理限制品質的根本拓撲；不得只在舊模型上無限疊加遮蓋層或細線。
3. 每輪先以固定鏡位、固定曝光與相同姿勢找出對人物真實感影響最大的缺陷，只處理一個可驗證的主要假設。
4. 技術通過但同鏡位 A/B 圖沒有可辨識改善的候選一律判退；不得因版本號增加而自動升分。
5. 所有接受與判退版本都保留可追溯的腳本、參數、報告與 Git 歷史。

## 品質範圍

### 解剖與外形

- 全身比例、頭骨、顴骨、下頜、鼻翼、鼻孔、眼眶、眼皮厚度、嘴唇轉折、耳朵、頸肩、手腳與主要關節必須在正面、側面、背面及斜角都合理。
- 裸體基礎必須具有連續且可變形的表面，不以服裝或頭髮遮掩解剖錯誤。
- 中性、眨眼、張嘴、微笑、轉頭、抬手、蹲姿與步行都要檢查輪廓和表面塌陷。

### 臉部、眼睛與皮膚

- 臉部必須具有明確的人類骨性結構與自然不對稱，避免蠟像、面具與程序化平均臉。
- 眼睛需有分離的角膜、鞏膜、虹膜、瞳孔、眼皮內壁、淚阜、濕潤線與睫毛；高光、折射、虹膜深度與眼球位置必須在多角度成立。
- 皮膚需具有受控的區域色差、粗糙度、微法線及次表面反應，禁止用整體變黑、提高曝光或過度平滑掩蓋問題。
- 眉毛、睫毛、唇面與髮際線必須保留纖維或表面結構，不得呈現貼紙、實心塊或外露鋼絲感。

### 毛髮

- 頭髮要有可讀的髮束層級：大形、中型髮束、細絲與少量飛散髮；髮根方向、分線、髮際線、鬢角、耳後、後腦與髮尾都需連續。
- 靜止時不得穿入頭皮、臉、耳、頸、肩或服裝；動態時需有根部固定、分區剛度、慣性、阻尼、重力與碰撞，不能整片僵硬或像金屬線。
- 毛髮材質需有方向性高光與根梢差異，但不可用純黑或高對比掩蓋拓撲問題。

### 分層、服裝與碰撞

- 明確建立並命名：身體、眼球組件、口腔、牙齒、舌頭、眉毛、睫毛、頭皮、頭髮、內層衣物、外層衣物、配件、骨架、控制器、物理代理與碰撞體。
- 裸體、單層服裝、多層服裝及動作姿勢都要驗證身體與衣物、衣物與衣物、頭髮與人體／服裝之間的間距。
- 禁止可見穿模。自動檢查須回報穿透頂點／點數、最小有號間距、測試姿勢及失敗位置；零穿透仍需通過人工多角度檢查。
- 衣服需有厚度、縫線、摺痕方向與合理材質反應，不能只是貼在裸體表面的彩色殼。

### 骨架、表情與動態

- 骨架比例、關節軸、蒙皮權重與臉部控制必須可由 Aevrynd 引擎讀取。
- 至少驗證中性、走路、跑步、蹲下、轉身、抬手、眨眼、張嘴與微笑。
- 動畫中不可出現關節糖紙變形、眼皮穿眼球、牙齒穿唇、衣物穿身體或頭髮穿模。

### 引擎與效能

- Blender 為權威製作來源；引擎使用可重建的匯出流程產生 GLB 或 Aevrynd 原生資產，不手動覆蓋不可重現的成品。
- 建立角色 LOD、材質／貼圖預算、骨骼與 morph 預算、毛髮品質級別和碰撞品質級別。
- 每個候選需記錄檔案大小、頂點／三角形、骨骼、morph、材質、貼圖、毛髮曲線或卡片數、CPU／GPU 時間與記憶體。
- 效能測試必須在 Aevrynd 實際角色場景執行，包含單角色近景、遊戲距離與多角色壓力情境；不得只以 Blender 視窗流暢度宣稱可用。

## 每輪必要流程

1. **基線**：固定來源版本、鏡位、燈光、姿勢、評分與已知缺陷。
2. **假設**：只提出一個主要改進，說明它應在畫面中產生的可見變化。
3. **製作**：用 Blender Python 或可追溯操作建立 2 至 3 個有限候選，避免無方向的大量版本。
4. **技術門**：檢查檔案可開啟、拓撲、命名、權重、非有限值、碰撞、動畫與匯出。
5. **視覺門**：以相同鏡位輸出正面、側面、背面、斜角、近景、全身及關鍵動作 A/B 圖。
6. **嚴格評分**：分別評估解剖、臉部、眼睛、皮膚、毛髮、服裝、動態、碰撞與效能；列出扣分原因及證據。
7. **決策**：只有同時通過技術與視覺門的候選可成為新主線；其餘明確標記判退，不污染正式資產。
8. **整合**：接受版本才匯入 Aevrynd 測試場景；通過引擎效能與畫面驗證後才可考慮替換網站預覽。
9. **歷史**：精確提交本輪 Blender 檔、生成腳本、報告、審核紀錄與必要引擎檔案，再推送指定 GitHub 分支。

## 固定驗收門檻

- 所有可見層在規定靜態與動態姿勢中：穿透數為 `0`。
- 技術報告不得缺少最小間距、測試姿勢、模型統計與引擎效能資料。
- 正式角色候選的整體嚴格分數至少 `85/100`，且臉部、眼睛、皮膚、毛髮、解剖、碰撞、動態與效能任一項不得低於 `80/100`。
- `70–84` 只能作為離線研究主線；低於 `70` 或無可見改善不得替換引擎展示資產。
- 不得自行提高分數；只有新增可重現證據或使用者的明確視覺判斷才能改分。
- 未經使用者確認，不發布、不替換網站正式女人偶，也不開始男人偶。

## 持續執行原則

每次持續執行都必須產生可驗證進度：新的受控候選、有效診斷、失敗證據、根本修正或引擎整合結果。不得只重跑相同測試、只增加版本號、只改文字報告或以技術通過冒充人物變得更逼真。若某種方法連續兩輪沒有可見改善，停止微調該方法，回到拓撲、比例、材質模型或動態架構重新設計。
